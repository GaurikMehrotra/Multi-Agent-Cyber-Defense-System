The checklist above remains applicable to each chosen archive. The source pages and WTMC2021 paper have now been read; the CNS2022 site and correction documentation were reviewed, but the CNS2022 full paper was not retrieved. Flow construction, duplicate rows, label schedules and dataset-specific topology make IDS benchmarks easy to misuse. Random splitting often lets nearly identical flows and identifier artifacts occur on both sides of evaluation. This pipeline deduplicates canonical flows, rejects conflicting labels, uses chronological boundaries without splitting identical timestamps, excludes IPs/time/labels from features, and tests held-out families and external data. It cannot automatically repair mislabeled public rows. Cross-dataset feature mapping and units must be verified by the researcher; results are invalid if schemas have different meanings.

## Published terms checked on 2026-10-11

* **CIC-IDS2017:** UNB's License section says the data are publicly available for researchers and requests citation of Sharafaldin, Lashkari and Ghorbani, ICISSP 2018. It does not state a standard SPDX license or an explicit general redistribution grant in the inspected section. Do not invent one, or assume the terms of a corrected archive are identical.
* **CSE-CIC-IDS2018:** UNB's License section explicitly permits redistribution, republication and mirroring, with a dataset citation and a link to the AWS page. This repository still never redistributes data. Verify the exact AWS link, access/cost terms and corrected-variant terms before downloading; do not use the full-bucket sync example on an 8 GiB laptop.
* **UNSW-NB15:** the page grants free academic-research use in perpetuity, requires agreement with the authors for commercial use, asserts copyright, and requires five citations. It is not an unrestricted commercial license. The five works listed there are Moustafa/Slay (MilCIS 2015); Moustafa/Slay (Information Security Journal 2016); Moustafa et al., geometric-area anomaly detection (IEEE Transactions on Big Data 2017); Moustafa et al., finite Dirichlet mixture models (Springer 2017); and Sarhan et al., NetFlow datasets (BDTA/WiCON 2020 proceedings). Verify complete bibliographic fields from those publications before submission.
* **CTU-13:** the authoritative FAQ states that permission need not be requested if the datasets are cited as specified. It names García, Grill, Stiborek and Zunino, Computers & Security 45 (2014), 100–123, DOI 10.1016/j.cose.2014.05.011. Neither the inspected dataset page nor FAQ specifies a standard Creative Commons/SPDX license. Per-file terms and redistribution rights therefore still need checking; a website's use permission is not a guessed archive license.

## Analyses read and implications

Engelen, Rimmer and Joosen, **“Troubleshooting an Intrusion Detection Dataset: the CICIDS2017 Case Study,”** IEEE SPW/WTMC 2021, pp. 7–12, DOI 10.1109/SPW53761.2021.00009, was retrieved and read in full. Its original-flow construction ends a TCP flow at the first FIN, creating TCP appendices; the paper reports appendices as 25.9% of the dataset. Timeout direction inheritance can then mislabel subsequent activity, and RST termination was ignored. The authors distinguish attempted activity from effective activity, identify problems with attack simulation, and show that aggregate scores can hide rare-family failures and shortcut learning. These are the paper's findings, not new measurements from this project. The supporting site also documents incorrect flag counts, timestamp leakage through Active/Idle features, a duplicated header feature, and later corrected-CSV revisions.

The site links newer work by Liu, Engelen, Lynar, Essam and Joosen, **“Error Prevalence in NIDS datasets: A Case Study on CIC-IDS-2017 and CSE-CIC-IDS-2018,”** IEEE CNS 2022, pp. 254–262. Its abstract and dataset-specific documentation were reviewed; the full paper has not been retrieved. The correction documentation distinguishes failed connections, startup/teardown artefacts and incorrectly assigned activity labels. Its download guidance says not to train an independent “Attempted” class; choose and disclose a mapping policy. For this project, exclude uncertain/attempted rows from the primary effective-attack benchmark and benign-only AE training, retain their count, and evaluate them separately. This is a conservative project policy, not a claim that all attempts are benign.

CTU's own documentation says the older unidirectional NetFlows should not be used and recommends its detailed bidirectional flow labels. It distinguishes Background from Normal and Botnet, and withholds complete mixed PCAPs for privacy. Therefore, background is not automatically benign, a CTU import must select confirmed Normal rows for AE training, and a flow-CSV benchmark cannot claim a measured Suricata baseline without corresponding authorized PCAP replay and aligned alerts. UNSW's source page documents hybrid real-normal/synthetic-attack generation and supplied partitions; it does not prove those partitions satisfy this project's temporal protocol. Reconstruct chronological splits from timestamp-bearing source files instead of treating the supplied training/test CSVs as leakage-safe.

**Selected starting point:** a small corrected CIC-IDS2017 flow sample, with its exact correction revision, archive hash and terms recorded. Cross-dataset evaluation needs a genuinely separate approved source with matching units and feature semantics; another CIC revision alone is not sufficient. No data have been obtained and no owner approval has been invented.

## Owner confirmation (required, secure local manifest)

Before downloading, record access date, license URL and exact terms/version, approved purpose, citation, variant, timezone/units, hashes and known-issues review. Decide whether “background” belongs in a benign-only AE training set; uncertainty is not benignness. Never redistribute raw rows.

Create `data/source.manifest.json` locally, **after your actual review**:

```json
{"dataset":"your-source-name","license_url":"authoritative reviewed URL","terms_reviewed_on":"YYYY-MM-DD","citation":"verified citation","known_issues_reviewed":true,"approved":true}
```

This is an example schema, not approval or a filled-in manifest. `src.eval.datasets` refuses ingestion without both explicit true confirmations. Supply a canonical CSV with `timestamp` (timezone), `src_ip`, `dst_ip`, `src_port`, `dest_port`, `protocol`, `duration` (seconds), `orig_bytes`, `resp_bytes`, `orig_pkts`, `resp_pkts`, `label` (0/1), `attack` (`benign` for label 0), `dataset`, optionally aligned `suricata_score` (0..1). Map vendor headers explicitly after checking units. The default generated-A/generated-B rows are algorithmic fixtures, **not real cross-dataset generalization evidence**.

## Rules and reference data

`configs/local.rules` is project-authored under MIT, intentionally alerts on harmless `example.com` DNS for sensor plumbing. No Emerging Threats or commercial rule set is bundled or downloaded. Verify a third-party rule set's current license, permitted redistribution, update policy and citations before replacing it. Do not interpret the demo rule as IDS coverage.

`configs/attack.json` contains one locally curated public technique ID T1046 and its reference URL, with no copied ATT&CK descriptions or STIX corpus. Load a broader official reference only with provenance/terms recorded. This project validates ID membership, not mapping correctness.
